The SAP S/4HANA implementation roadmap at a glance

The roadmap follows the six SAP Activate phases. Discover happens before the programme is formally mobilised; the five delivery phases then run for about 15 months to go-live, followed by an ongoing Run and Optimize phase. The timeline below is for a Finance-led S/4HANA programme for a mid-to-large company with several legal entities; a single-country rollout on SAP S/4HANA Cloud Public Edition can be considerably shorter.

Phase 0 – Discover

Often called phase zero, Discover answers whether and how to move to SAP S/4HANA before money is committed to delivery. The team builds the business case, runs the SAP Readiness Check and custom code analysis, assesses data quality and volume, and decides the transition approach (greenfield, brownfield or selective data transition) and the deployment model (RISE with SAP, public cloud or on-premise). The output is a high-level scope, a release plan, a budget and a shortlist of implementation partners.

We list the full set of outputs, with owners and exit criteria, in a separate checklist: SAP S/4HANA phase zero deliverables list.

Phase 1 – Prepare

Governance comes first: steering committee, PMO structure and RACI, and the risk and issue log. In parallel the team audits the current ERP, sets a data quality baseline and checks infrastructure readiness. The AI foundation starts here too, with an inventory of agentic AI use cases, an AI governance framework and LLM vendor selection, alongside stakeholder mapping and a change impact assessment. AI in this phase: automated landscape discovery and gap analysis.

Phase 2 – Explore

Fit-to-standard workshops based on SAP Best Practices drive delta design decisions and process blueprint sign-off. The data strategy covers migration, master data governance and the start of data cleansing. Technical architecture defines cloud topology (BTP or Azure), integration and security. For Finance, this is where the Controlling model is fixed; see our SAP S/4HANA CO design guide and, for multi-country programmes, the localization guide. The AI use cases are designed in detail: a finance AI agent, a PMO copilot and a conversational ERP experience. AI in this phase: process mining to detect fit-gaps.

Phase 3 – Realize

The core build covers FI/CO and MM/SD configuration, custom development in ABAP or BTP, and integrations with SAP Integration Suite, including e-invoicing through SAP Document and Reporting Compliance where mandates apply. The AI agents are built in parallel: finance close, PMO status reporting and invoice automation. Data migration runs extraction, migration cockpit loads and reconciliation over several mock loads, followed by unit, string, integration and performance testing. AI in this phase: automatic test-case generation and defect triage.

Phase 4 – Deploy

User acceptance testing and key-user certification lead into cutover rehearsals, the final data load and the go/no-go decision. Training is role-based and includes how to work with the AI agents. Go-live is followed by a hypercare war room and incident management. AI in this phase: real-time cutover monitoring and anomaly alerts.

Phase 5 – Run & Optimize

After stabilisation and hypercare exit, the focus moves to process KPI dashboards, quarterly value reviews and an enhancement backlog. New agents are rolled out, models are retrained on feedback, and an SAP Centre of Excellence and AI governance are set up to build internal capability. AI in this phase: autonomous period close, predictive analytics and self-healing processes.

Who does what: RACI summary

Most roadmap slippage traces back to unclear decision rights. The short version: the executive sponsor is accountable for the investment and the go/no-go call, business process owners are accountable for the design and UAT sign-off, the PMO owns the plan and the cutover, and the solution architect owns technical integrity.

AI agents in the roadmap

Across the programme run four core workstreams and six AI agents that take on tasks, make bounded decisions and work alongside the project team.

  • Finance Close Agent – posts month-end journals, reconciles intercompany balances and reports variances.
  • PMO Status Agent – aggregates data from Jira, SAP and email to produce weekly status reports and escalation alerts.
  • Invoice Processing Agent – PO matching, exception handling and payment proposals, with no manual touch for standard invoices.
  • Master Data Agent – enforces data quality rules, flags duplicates and triggers cleansing workflows.
  • Cutover Monitor Agent – tracks cutover tasks in real time, predicts delays and suggests remediation.
  • Conversational ERP Agent – lets users query balances, open items and KPIs in natural language.

All agents follow the same principles: native deployment on SAP BTP, access through standard SAP APIs and OData, human-in-the-loop escalation, a full audit trail and continuous improvement of the underlying models.

SAP S/4HANA implementation roadmap: FAQ

How long does an SAP S/4HANA implementation take?

For a multi-entity Finance-led programme, plan on 12–18 months from Prepare to go-live; this roadmap assumes about 15. Single-country public cloud projects using standard scope can go live in 4–8 months, while global multi-wave rollouts run for several years.

What are the SAP Activate phases?

Discover, Prepare, Explore, Realize, Deploy and Run. Each ends with a quality gate where agreed deliverables are reviewed before the next phase starts.

What is phase zero in an SAP S/4HANA project?

Phase zero is the Discover work done before delivery is mobilised: business case, readiness and custom code checks, the transition approach, scope, budget and partner selection. See the phase zero deliverables list.

Does the roadmap change for greenfield and brownfield?

The phases stay the same; the content shifts. A brownfield system conversion puts more weight on readiness checks, custom code remediation and technical conversion rehearsals, while a greenfield implementation spends more time in fit-to-standard design and data migration.
