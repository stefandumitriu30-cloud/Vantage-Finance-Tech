What changes when ERP programs include AI agents

Cloud ERP programs increasingly include agentic AI: software agents that carry out multi-step tasks such as invoice matching, exception triage, forecasting or narrative reporting inside the ERP. On SAP this arrives through Joule and Joule Agents; on Oracle through embedded agents in Fusion Applications and AI Agent Studio. Because these capabilities often come switched on in standard releases, decisions about which agents run, on which processes and with how much autonomy have to be made during design, not after go-live.

The guide's core message is that classic PMO discipline (RAID logs, RACI, stage gates, cutover rehearsals, hypercare) stays essential, but each artifact needs an AI-aware extension.

Three shifts behind the modern PMO

  • From big-bang to continuous delivery – both platforms ship quarterly releases, so the PMO runs a recurring release-adoption process alongside the main timeline.
  • From fixed scope to a living AI backlog – vendors add and change agent capabilities between releases, so AI scope must be triaged continuously.
  • From IT-led to cross-functional governance – decisions on agent autonomy and data access need Finance, Risk and Audit, Data Privacy and process owners alongside IT.

Governance and roles

The guide adds one forum and one role to the usual structure. The AI Governance Board approves each agent's autonomy level, guardrails and data access before go-live, meeting every two weeks during build and monthly afterwards. The AI/Agentic Solution Owner is accountable for the agent backlog and autonomy classifications. These sit alongside the steering committee, PMO core team, workstream leads forum and change advisory board.

Phase by phase

Each phase, aligned with SAP Activate and Oracle's methodology, gets both core PMO activities and AI workstream activities:

  1. Discover & Prepare – business case, charter and governance, plus an AI opportunity assessment scored by data readiness, risk and value, and the AI Governance Board charter.
  2. Explore – fit-to-standard design, plus a specification for every agent: scope, triggers, data, decision boundaries, autonomy level, human checkpoints and audit logging, signed off before build.
  3. Realize – iterative build, plus agent configuration, unit testing with edge cases, the agent register and runbooks, and data quality thresholds.
  4. Deploy – SIT, UAT and cutover rehearsals, plus agent behaviour testing, end-to-end tests of human handoffs, audit log validation and a documented go-live autonomy level per agent.
  5. Run & Hypercare – stabilisation, plus agent KPI monitoring, a board review before raising any agent's autonomy, and monthly re-validation after vendor updates.

Autonomy levels and the agent register

Every agent should be classified as advisory (it recommends, a person decides), approve-then-execute (it prepares, a person approves) or autonomous within bounds (it acts within approved limits and escalates exceptions). The recommended default is to launch every agent at the most conservative level feasible and raise it only with evidence from hypercare; lowering it should be a same-day operational decision.

A living agent register records each agent's owner, platform, data access, autonomy level, escalation rules, audit log location, KPIs, review date and status.

New risks and testing

The RAID log gains AI-specific categories: data quality, model drift after vendor updates, over-reliance on recommendations, auditability, informal scope creep, vendor dependency and change fatigue. Testing adds a dedicated agent behaviour track: scenario tests against historical transactions with known outcomes, edge-case and adversarial tests, confidence-threshold tuning, regression after every release, and bias checks for sensitive processes. The guide calls the reusable scenario library the single most valuable testing asset.

Change management and value

Change management has to explain what each agent does and does not do, train people to challenge agent output rather than rubber-stamp it, and run escalation drills before go-live. For value reporting, the PMO should baseline KPIs before go-live and report AI-driven gains separately from general process improvements, using metrics such as agent-handled volume, accuracy, escalation rate, override rate and time saved.
